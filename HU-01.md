# HU-01 - Migrar contraseñas legacy de forma segura

## Origen

- **H-AUTH-02 (Pendiente):** la migración omite cualquier contraseña que comience con `$2a$`, `$2b$` o `$2y$`, aunque sea texto plano; además, la inicialización registra y absorbe errores de migración. Evidencia: `auth/src/main/java/com/bcp/workshop/auth/LegacyDatabase.java:25-30,67-92`.

## Contexto

La base de datos puede contener contraseñas legacy en texto plano que deben migrarse a BCrypt. Actualmente, `isBcryptHash` decide si omitir una fila basándose únicamente en el prefijo, y `initialize` permite continuar aunque falle la inicialización. Esto puede dejar credenciales sin migrar o el servicio iniciado con la base de autenticación en un estado no confiable. La corrección debe mantener la autenticación existente y hacer la migración idempotente.

## Criterios de aceptación

- [ ] La migración distingue los hashes BCrypt válidos del texto plano sin basarse únicamente en el prefijo `$2a$`, `$2b$` o `$2y$`.
- [ ] Se agrega una prueba de regresión para una contraseña en texto plano que comienza con uno de esos prefijos; tras migrar, el valor almacenado ya no es el texto original y la contraseña original sigue autenticando.
- [ ] Se conserva una prueba de idempotencia: ejecutar la migración más de una vez no vuelve a modificar un hash ya migrado.
- [ ] Si falla la inicialización o migración de la base de datos, el fallo se comunica al arranque y la aplicación no continúa como si la base estuviera lista.
- [ ] Se agregan pruebas que comprueban el comportamiento ante un fallo de inicialización, sin afirmar resultados que no se hayan ejecutado.
- [ ] Se conservan el contrato de `POST /auth/login` y las consultas SQL parametrizadas.
- [ ] Se valida el cambio con `python tools/lab.py test auth` desde la raíz del monorepo; el resultado queda registrado como **No ejecutado** hasta que se ejecute realmente.
